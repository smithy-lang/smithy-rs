C03: media-typed prefix-header decoding
Validated 2026-10-14 against freshly generated legacy and schema servers.

Source evidence
  HttpBindingGenerator.generateDeserializePrefixHeaderFn delegates each map
  value to HttpHeaderValueParserGenerator.renderHeaderValueParser. For a string
  with @mediaType, Kotlin emits comma/quote tokenization, base64 decoding, UTF-8
  validation and scalar token-count validation. Schema previously passed the
  raw header text to the handler without decoding or validating it.

Fix
  MediaHeaderMapDeserializer processes matching headers in order, delegating
  each entry to HeaderValuesDeserializer. This reuses the existing tokenization,
  base64 and UTF-8 handling. It counts parsed tokens rather than physical header
  instances, so an empty instance plus a valid instance still supplies one value.
  Plain prefix-header strings and query maps retain their existing reader.

Strict compatibility includes a legacy panic
  Kotlin's prefix parser expects a parsed value whenever a matching header name
  exists. One or more completely empty instances produce no tokens, triggering
  its expect. Schema deliberately preserves that panic and its message to meet
  the requested strict compatibility target. The tests catch and compare it
  explicitly; a panic is not counted as a successful HTTP response.
  Quoted-empty and whitespace-only values do produce an empty string token.
  Entry ordering also matters: an empty header before a different invalid-UTF-8
  header panics; the reverse ordering returns 400. Parsing entries in sequence
  preserves that behavior instead of validating the whole map up front.

Test contract and coverage
  Generate fresh REST JSON and REST XML servers with schemaSerde=false, then
  schemaSerde=true, using HTTP 1.x. Each legacy server must meet 36 explicit
  controls. Handlers echo parsed inputs. Compare status, all response headers
  and exact body bytes; for expected panics, compare the panic and its message.
  Covers quoted/unquoted base64, Unicode, decoded whitespace/NUL/newline,
  non-JSON decoded text, invalid base64/padding/UTF-8, comma and quote parsing,
  repeated headers, empty instances, mixed-case names, multiple map entries,
  an empty suffix, and mixed-invalid-header ordering. Direct media headers
  decode; media-typed query values and query maps remain undecoded.
  Logging and response prefix-header encoding remain separate audit items.
