C01: trailing slashes in HTTP URI templates
Validated 2026-10-14 against freshly generated legacy and schema servers.

Problem and fix
  Legacy ServerHttpBoundProtocolGenerator.serverRenderUriPathParser consumes
  httpTrait.uri.segments. Smithy's UriPattern drops trailing empty template
  segments, as does schema routing. Schema extract_labels previously retained
  them. Valid routed requests then failed with 400, or a greedy label lost its
  final slash. extract_labels now removes trailing template slashes before
  splitting. Request paths are preserved, including empty greedy segments.

Repeat on another machine (from the repository root)
  python3 tools/schema-serde-compat/run_c01.py

  This uses the existing audit runner's runtime_snapshot helper. It copies the
  current runtime into an isolated build, excludes Markdown, and replaces doc
  include attributes only in that copy. It neither reads nor restores Markdown.
  Use the repository Rust toolchain, Java/Gradle and Python 3. Generated crates,
  Cargo.lock files, cargo logs, source hashes and observations remain under
  tools/schema-serde-compat/.runs/C01-<UTC timestamp>/.
  Exit zero means the JUnit regression passed; a nonzero exit requires reading
  gradle.log and the per-service cargo logs. comparison.json records HTTP diffs.

  The JUnit regression also runs directly through :codegen-server:test with
  --tests '*TrailingSlashLabelsCompatibilityTest'. The Python entry point is
  preferred for preserved artifacts and builds that omit repository Markdown.

Live reference and assertions
  The checked-in model is models/trailing-slash-labels.smithy in this directory's
  parent. Both REST JSON and REST XML are generated with schemaSerde=false and
  schemaSerde=true, using HTTP 1.x. All four servers are compiled and exercised
  through their actual routing services; no hand-written reference parser.
  Handlers echo the parsed label as an HTTP payload.
  Each legacy server must first meet 32 explicit status/value controls. Then
  every schema status, response header and exact response byte must match its
  live legacy counterpart. This prevents shared early rejection from passing.
  Logging compatibility is a separate audit item and is not asserted here.
