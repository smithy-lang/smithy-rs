Current design (October 20, 2026)
- Blob handlers take their ordinary operation input, containing a ByteStream.
- For REST, HTTP-bound metadata is deserialized and validated before invoking the handler;
  the live body is passed through without collection.
- The deferred StreamingInput API, StreamingRequestDecoder, and streaming_input
  runtime module have been removed.
- RPC v2 CBOR streaming blob inputs are collected under the selected operation's
  body limit and timeout, then decoded with the existing CBOR codec. The blob is
  converted to a buffered ByteStream, and all fields are validated before dispatch.
  Duplicate streaming members retain legacy last-value behavior. CBOR blob outputs
  remain supported.
- Incremental CBOR decoding and its handler contract for trailing fields and
  validation are deferred. No completion/session API is exposed to handlers.
- Unsupported event streams also return empty HTTP 501.
- The notes below describe the superseded implementation and its historical tests.

Streaming blob inputs: implementation and verification

Implemented
- StreamingOperationShape::deserialize_streaming_input takes an owned
  Request<RequestBody> and SharedServerProtocol (phase 1).
- ServerProtocol::deserialize_data_stream is a synchronous factory for an owned
  StreamingRequestDecoder. The existing synchronous deserialize_request remains.
- Generated blob handlers accept StreamingInput<UploadInput>. UploadInput and its
  builders contain ordinary fields only; their runtime schema retains the blob
  member. The generated member schema selects the wire name without a runtime scan.
- StreamingInput<T> exposes data: ByteStream and is_present(). finish(&mut self)
  reads trailing fields and validates T. Calling finish before blob EOF returns
  StreamNotFinished without draining, and cancellation leaves it resumable.
- into_input_and_blob(self) collects and finishes, returning (T, Option<Blob>).
  into_blob(self) also validates the complete input, then returns just Option<Blob>.
  These methods reject previously delivered bytes. None preserves absence;
  Some(empty) preserves a present empty blob. REST's payload is always present.
- Collection honors the selected operation's byte limit, counting all raw wire
  bytes including prefix/framing, and uses one deadline across collection+finish.
  Polling defaults are unchanged: 64 consecutive ready frames for collection,
  32 for ordinary streaming. The parser also yields during buffered framing work.
- CBOR definite/indefinite byte strings stream incrementally. Ordinary values are
  passed to the existing configured codec in complete single-member envelopes.
  No borrowed deserializer survives an await and no mutex is held across an await.
- REST continues exposing raw payload bytes. Event streams retain their existing
  glue, initial-frame handling, and encoding paths.
- streaming_blob_is_document() has been removed from runtime and codegen.
- No shared serde trait changes. No Rust runtime source changes outside
  aws-smithy-http-server. Nothing committed or pushed.

Approved compatibility differences and error timing
- Fresh legacy duplicate baseline: {data: h'01', data: h'02'} succeeds and uses
  h'02'. HTTP 200, content-type application/cbor, smithy-protocol rpc-v2-cbor,
  content-length 9, body bf64646174614102ff.
- User explicitly approved rejecting duplicate streaming members. The new session
  rejects them at finish when they follow the delivered blob, because delivered
  bytes cannot be replaced. A duplicate before any blob is exposed can fail during
  preparation. Null still counts as a key occurrence.
- Validation and parse errors after the blob are returned to the handler. The
  handler decides how to respond; the runtime cannot replace a response that the
  handler has already started. The comparison harness explicitly applies the
  protocol rejection renderer to late errors; this is test handler policy.
- Trailing bytes remain invalid. The comparison rejection is HTTP 400,
  application/cbor, body a0. Required-field/constraint errors retain the generated
  validation exception conversion, including with private generated builders.
- Existing CBOR output streaming framing is unchanged by this task: indefinite
  blob chunks differ intentionally from legacy definite blob output. REST output
  remains raw. This work does not fix client-side CBOR blob extraction.
