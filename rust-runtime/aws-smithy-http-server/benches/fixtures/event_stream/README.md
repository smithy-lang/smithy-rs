# Event-stream runtime benchmark fixtures

These files are a **one-time copy of generated code**, not hand-written schema walkers.
The source is the `event-stream-bench-rest-json-schema` projection generated by
`codegen-server-test` from
[`common.smithy`](../../../../../codegen-server-test/benchmarks/event-stream/model/common.smithy)
and `rest-json.smithy`, with `http-1x: true` and `schemaSerde: true`.
The same copied types are used with both REST JSON and RPC v2 CBOR at runtime.

The snapshot was taken on 2026-10-18 from:

```text
codegen-server-test/build/smithyprojections/codegen-server-test/
    event-stream-bench-rest-json-schema/rust-server-codegen/src/
```

| Local file | Copied generated code |
| --- | --- |
| `model.rs` | Events, StructuredEvent, BinaryEvent, StructuredData, Nested, their schemas, serde walkers, and builders |
| `error.rs` | StreamFailure and EventsError, including the error schema and serde walker |
| `event_stream_serde.rs` | Generated dispatch implementations and runtime marshaller/unmarshaller aliases |
| `output.rs` | DownloadOutput, its schema, and its metadata serializer |

Adaptations remove the unrelated framework validation shape, SDK-only `Constrained`
implementations, and unused output builders. Rustfmt and a fixture header were applied.
The copied schema definitions, serde walkers, event dispatch, and necessary builders
retain their generated behavior. Dead-code warnings are allowed in the snapshots
because generated convenience methods are not all used by the benchmark.

The benchmark imports these local files. It has no generated SDK dependency,
`include!` of generated output, build script, or Gradle prerequisite. It runs even
when the generated projection is absent. Changes to codegen do not update the
snapshot automatically; refreshing it is an explicit, reviewed change.

From the repository root:

```sh
cargo bench --quiet --manifest-path rust-runtime/aws-smithy-http-server/Cargo.toml \
    --bench event_streams

# Run every case once, with preflight checks, without collecting timings.
cargo bench --quiet --manifest-path rust-runtime/aws-smithy-http-server/Cargo.toml \
    --profile dev --bench event_streams -- --test
```

The 72 cases cover both protocols:

- Structured and binary payloads of 64 B, 1 KiB, and 64 KiB: warmed event
  serialization, first-event serialization with a new marshaller, deserialization,
  complete frame encoding, and complete frame decoding (60 cases).
- Modeled exception serialization, deserialization, encoding, and decoding (8 cases).
- Response-body construction and complete draining of 64 events of 1 KiB,
  including CBOR's initial-response metadata frame (4 cases).

Frame encoding/decoding includes CRC work. Payload construction and cloning are
outside timed serialization/encoding batches. Deserialization includes constructing
owned modeled values. A fresh marshaller is created per response-body iteration;
its header cache warms within that stream. Response-body timing excludes sender
fixture construction and includes executor entry and every body poll, without
collecting the whole response or parsing it again. Preflight independently checks
headers, raw binary payloads, event equality, modeled exceptions, initial metadata,
CRCs, event count, and end of stream.

This measures the schema event-stream runtime only. It does not compare legacy serde,
route requests, invoke handlers, or use sockets. For the generated legacy/schema
server comparison, use
[`codegen-server-test/benchmarks/event-stream`](../../../../../codegen-server-test/benchmarks/event-stream/README.md).
