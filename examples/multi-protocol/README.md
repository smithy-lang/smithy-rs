The service shares one set of handlers across AWS JSON 1.0/1.1, REST JSON, REST XML and RPCv2 CBOR.

`make codegen` generates one server and one schema client (REST JSON by default).
`make test` regenerates both and runs the client and wire suites. The client tests select each of the five protocols with `Config::builder().protocol(...)`; one test exercises all five against the same listening server. The wire tests also exercise the real service directly without a listening socket and select REST XML explicitly by Content-Type.

The shared synthetic model includes ordinary structure/union payloads with distinct member/target XML names, response status/header/prefix bindings, nested collections and union variants, blobs and timestamps, populated modeled errors, generated builder defaults, and absent/empty/null sparse values. JSON-only service profiles additionally include DocumentValues; this operation is outside the all-five-protocol server.

The `scenario` input selects populated, absent, empty, default, override or error responses where applicable. REST carries it in `x-scenario`; RPC carries it as an ordinary body member. Tagged response fixtures drive the fuzz handlers, and request fixtures seed these selectors.

Native protocol tests assert the declared wire contract. A/B tests compare independently generated legacy and schema servers using the same model and inputs. The generic fuzz model has explicit reductions: see `tools/multi-protocol-ab-fuzz/README.md` and the generated model-projection manifests. A passing reduced-model comparison does not establish coverage for excluded operations or members.

Current validation and remaining failing assertions are recorded in `validation/multi-protocol-enrichment/` and `validation/multi-protocol-example/report.md`.

`Ping` models explicit empty structures. `NoInputOutput` has neither an input nor an output declaration (Smithy Unit). The wire test checks that CBOR returns an empty map for Ping and no body or Content-Type for NoInputOutput.

Run `python3 tools/schema-serde-compat/run_mainline_client.py` from the repository root for a fresh comparison with HTTP/1.x servers generated by `~/kaam/smithy-rs-latest`. It uses the same single schema client, captures both directions of HTTP traffic, and records unavailable mainline cases explicitly. See `tools/schema-serde-compat/mainline-client-results.txt` for the evidence and limitations.

Current verification: client tests 23 passed/10 failed; wire tests 6 passed/1 failed. The failures include server routing differences as well as client serialization gaps. In particular, AWS JSON Ping and NoInputOutput succeed against mainline but return 404 on the schema multiprotocol server when Content-Type is absent. Restoring Content-Type while keeping the body empty succeeds on both. RPC requests missing ordinary/event-stream initial data fail against mainline too; corrected control requests succeed. The mainline comparison test is opt-in and records outcomes; it does not mark failing protocol cases as successes. `make test` still exits with a test failure.
